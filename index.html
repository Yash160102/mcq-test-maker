✦ QuizMate — your AI assistant · ask anything

            
QuizMate is a general AI assistant — ask it any question: general knowledge, explanations, coding help, study help, or anything else. It can also read the file you just loaded, chat about that content, and — when the file is study material rather than a ready-made question paper — write a brand-new MCQ test from that content. A file is optional, never required to chat.

          

          Before the test
        

        
Setup note: QuizMate uses a small backend function at /api/chat on Vercel reading GROQ_API_KEY from the host's environment variables (the key is never in this page). It works as a general AI assistant (mode: "general" — no file or content required), as well as for content chat, MCQ generation and post-test explanations. Models: openai/gpt-oss-120b is the primary, with meta-llama/llama-4-scout-17b-16e-instruct (llama-4-scout) and qwen/qwen3-32b (qwen3) as fallbacks — GROQ_MODEL in Vercel can override the primary. A Groq 404 means the model is unavailable for that key, not that the function is missing. Until that function is deployed you'll see a clear “backend not configured” message — uploading files and taking parsed tests keep working either way. These panels live on this home screen only, so they're never available during a test.

What format should my file be in?

        
Works with PDF, Word (.docx) and TXT files — the same layout rules apply in all of them. Two answer styles are supported — use either, or mix them in one file. Questions can be numbered or unnumbered, and can span multiple lines including code / technical lines before the actual question sentence — all of it is kept as the question text. For Word, just type or paste your questions as normal paragraphs in a .docx file (older .doc files should be re-saved as .docx first).

        
    
          
  • Style 1 — inline marker (no Answer line needed): put ✓ Correct answer at the end of the correct option. Variants ✓, ✔, Correct answer, [Correct] also work. The marker is stripped from the option shown in the test.
    • 
          
  • Multiple answers: some questions can have more than one correct answer. Mark every correct option with ✓, or list them on the answer line — e.g. Answer: A, C or Answers: B and D. In the test those questions say “Select all that apply” and let you pick multiple options. You score the point only when you pick exactly the correct set (no missing, no extra).
    • 
          
  • Style 2 — answer line: Answer: B, Ans: (C), or Correct Answer: A on its own line — use commas / “and” for multiple answers.
    • 
          
  • Options: A. , A) , (A) — long / multi-line options are joined automatically.
    • 
          
  • No answer marker at all? The question is still included, marked unscored — it won’t affect your score.
    • 
          
  • Explanations after Explanation: are kept for review.
    • 
        

      

      

        
Example — inline ✓ style

        
A data analyst runs the following on a 25 GB table:
DROP TABLE IF EXISTS sales.orders;
Afterwards, SHOW TABLES no longer lists sales.orders, but the underlying Parquet files are still present. Which statement best explains this behaviour?
A.  Tables larger than 10 GB always retain their files when dropped.
B.  The table was an external (unmanaged) table, so DROP TABLE removes the metadata while the data files are left untouched.   ✓ Correct answer
C.  Unity Catalog requires VACUUM before files are deleted.
D.  DROP TABLE always preserves files unless CASCADE is supplied.

An “Answer: B” line instead of the ✓ marker also works.

        For Yash: the Vercel backend file to add (api/chat.js)
        
Deploy this page on Vercel together with this one function file, then set GROQ_API_KEY in Vercel → Project → Settings → Environment Variables and redeploy. This page sends top-level fields only — POST { mode, content, question, options, correctAnswers, userChoice, message, count, history } — mode: "general" with just message and history (no file, content or question required — this is how QuizMate answers any general question, before or after a test), mode: "chat" with the uploaded file's text in top-level content (truncated to 12,000 chars) plus message and history when the question is about that file, mode: "generate" with the file text in top-level content plus a question count, and mode: "explain" with top-level question (string), options (array of raw option strings, no “A. ” prefix), correctAnswers (array of letters like ["B"]), userChoice (a letter, an array of letters, or "skipped") plus message — and expects { reply } back (for generate, the reply is the new questions written in this app's normal text format, so the page can parse, preview and score them like any uploaded paper). Models in the backend below: primary openai/gpt-oss-120b, fallbacks meta-llama/llama-4-scout-17b-16e-instruct (llama-4-scout) and qwen/qwen3-32b (qwen3); GROQ_MODEL in Vercel Environment Variables can override the primary (add it next to GROQ_API_KEY and redeploy). A Groq 404 in that backend means the model is unavailable for that key, not that the function is missing — it tries the fallbacks and, if all fail, returns 502 with the Groq message instead of passing a 404 through. The backend below also accepts the older context.* / text shapes as a fallback, but this page no longer sends fields nested under context.

        
// api/chat.js — Vercel serverless function (separate deploy file, NOT part of this page)
// Contract (top-level fields): { mode, content, question, options, correctAnswers, userChoice, message, count, history }
export default async function handler(req, res) {
  if (req.method !== 'POST') return res.status(405).json({ error: 'Method not allowed' });
  const key = process.env.GROQ_API_KEY;
  if (!key) return res.status(500).json({ error: 'GROQ_API_KEY is not set on the host. Add it in Vercel Environment Variables and redeploy.' });
  const { mode, message, content, question, options, correctAnswers, userChoice, count, history, context, text } = req.body || {};
  const contentText = content || text || (context && (context.text || context.content)) || '';
  let system, user;
  if (mode === 'general') {
    // General AI assistant — no file, content or test question required.
    if (!message) return res.status(400).json({ error: 'Missing required field: message' });
    system = 'You are QuizMate, a helpful general AI assistant. Answer any question the user asks — general knowledge, explanations, coding help, study help, writing, maths, or anything else — clearly and helpfully, like a normal AI assistant. Never refuse just because no file was uploaded or the question is unrelated to a test or document.';
    user = message;
  } else if (mode === 'generate') {
    if (!contentText) return res.status(400).json({ error: 'Missing required field: content' });
    system = 'You write multiple-choice questions from study content. Reply ONLY with the questions, each as: the question text, then its options on their own lines as "A. ...", "B. ...", "C. ...", "D. ...", then a line "Answer: X" (use "Answer: X, Y" only for a genuine multi-answer question). No intro, no commentary.';
    user = 'Write ' + (count || 10) + ' MCQs from this content:\n' + String(contentText).slice(0, 12000);
  } else if (mode === 'chat') {
    if (!message) return res.status(400).json({ error: 'Missing required field: message' });
    if (!contentText) { system = 'You are QuizMate, a helpful general AI assistant. Answer any question clearly and helpfully, like a normal AI assistant.'; user = message; }
    else {
      system = 'You are QuizMate, a helpful general AI assistant. The user has loaded the content below. If their question is about that content, answer using it. If their question is unrelated to the content, answer it normally from your general knowledge — never refuse or force them back to the content.';
      user = 'Content:\n' + String(contentText).slice(0, 12000) + '\n\nQuestion: ' + message;
    }
  } else {
    // mode: "explain" (default)
    const qText = question || (context && context.question) || '';
    if (!qText) return res.status(400).json({ error: 'Missing required field: question' });
    if (!message) return res.status(400).json({ error: 'Missing required field: message' });
    const opts = Array.isArray(options) ? options : ((context && context.options) || []);
    const correct = Array.isArray(correctAnswers) ? correctAnswers : ((context && context.correctAnswers) || []);
    const choice = (userChoice !== undefined ? userChoice : ((context && (context.userChoice || context.userAnswers)) || 'skipped'));
    system = 'You are QuizMate, a friendly general AI assistant. The test is already finished. When the student asks about the question provided, explain clearly why the correct answer is correct and why their choice was wrong, and do not invent a different answer key. When they ask a general question unrelated to that question, answer it normally from your general knowledge.';
    user = 'Question: ' + qText + '\nOptions: ' + JSON.stringify(opts) + '\nCorrect answers: ' + JSON.stringify(correct) + '\nUser choice: ' + JSON.stringify(choice) + '\n\nStudent asks: ' + message;
  }
  // Groq models: primary openai/gpt-oss-120b, then llama-4-scout and qwen3
  // fallbacks. GROQ_MODEL (Vercel env var) overrides the primary when set.
  // A Groq 404 / model_not_found means the MODEL is unavailable for this key
  // — NOT that this function is missing — so it is never passed through as
  // this function's own 404: try the next model, and if every model fails
  // return 502 with the Groq message, so the page can show it plainly.
  const MODELS = [...new Set([process.env.GROQ_MODEL, 'openai/gpt-oss-120b', 'meta-llama/llama-4-scout-17b-16e-instruct', 'qwen/qwen3-32b'].filter(Boolean))];
  let groqError = '';
  for (const model of MODELS) {
    const r = await fetch('https://api.groq.com/openai/v1/chat/completions', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json', Authorization: 'Bearer ' + key },
      body: JSON.stringify({ model: model, messages: [{ role: 'system', content: system }, { role: 'user', content: user }] })
    });
    const data = await r.json().catch(() => null);
    if (r.ok) return res.status(200).json({ reply: data.choices[0].message.content });
    groqError = (data && data.error && data.error.message) || ('Groq request failed (' + r.status + ')');
    if (r.status !== 404) break; // only a model-not-found 404 falls through to the next model
  }
  return res.status(502).json({ error: 'Groq model unavailable: ' + groqError + ' (tried: ' + MODELS.join(', ') + '). A Groq 404 means the model is unavailable for this GROQ_API_KEY, not that api/chat.js is missing — set GROQ_MODEL in Vercel to a model your key can use.' });
}
